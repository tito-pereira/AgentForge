# DT-14 — Session Handoff is derived evidence

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-14, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

Switching providers requires portable context for continued work. Agent descriptions of edits, checks or blockers may differ from observed project state.

## Decision

Treat Session Handoff as a derived artifact. It can summarize changes, tests, failures, blockers and next steps. Any change to contracts or approved decisions must go through their existing authorities.

## Rationale

A handoff can carry useful continuity while preserving the provenance and authority of durable project facts.

## Consequences and compatibility

Reconcile observed facts before using a handoff with Project State and the Work Item to build the next Context Projection. Preserve existing contract publication, human approval and independent Validation boundaries. A claim in a handoff supplies no approval or validation result.

## Affected phases

Phase 4 introduces Session Handoff and provenance. Phase 5 uses it to carry context across providers. Phase 8 presents session and context evidence.

## Non-goals

Phase 0 defines the authority boundary only. Automatic approval, canonical state mutation and dependence on a provider's private conversation history are outside this decision.

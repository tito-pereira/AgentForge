# DT-19 — Keep source-first installation to one setup command

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-19, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

The Windows baseline installs per user from source and exposes the `corinthos` command. Desktop builds will add toolchain prerequisites that setup must handle.

## Decision

Keep the public source-first acquisition and setup flow unless an explicit future decision changes it.

```powershell
git clone <repository>
cd Corinthos
.\install.ps1
corinthos
```

Supported Windows and PowerShell plus working Git are the explicit prerequisites for acquiring the checkout and launching setup. After clone, setup detects existing prerequisites. When required, it configures pinned Rust and Node for the build, installs frontend dependencies deterministically, builds the GUI, and checks and installs WebView2. If Microsoft C++ Build Tools are missing, setup uses the official installer and may request UAC once for that system prerequisite. Setup then resumes automatically.

## Rationale

A one-command setup preserves the existing onboarding experience as desktop build requirements grow.

## Consequences and compatibility

Preserve the per-user installation, the final command, compatible global state, project data and reinstall recovery. Continue verifying pinned artifacts and honoring the explicit provider-probing boundary. The baseline uses the Windows .NET Framework compiler for its local launcher and needs network access for uncached artifacts.

## Alternatives

Manual desktop toolchain setup is excluded from the standard onboarding path. A single setup command can still produce a system elevation prompt when an official prerequisite requires it.

## Affected phases

Phase 1 verifies a desktop build spike. Phase 8 integrates GUI launch behavior. Phase 9 delivers and tests automated setup from a clean Windows machine.

## Non-goals

Phase 0 records the existing installer and future obligations. Desktop tooling, installer changes and public release packaging belong to later decisions or phases.

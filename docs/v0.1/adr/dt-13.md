# DT-13 — Deterministic context retrieval first

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-13, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

Existing project data, exact contracts and revisions, Workflow and Validation records, lifecycle evidence and repository metadata supply attributable context. Later phases add Work Items, Agent Sessions and import indexes to these sources.

## Decision

Retrieve structured relationships and traverse the dependency graph first. Use lexical search and SQLite FTS where applicable, with a clear fallback. Semantic retrieval comes later. Each Context Projection is immutable, identified by digest and bound to the exact sources that produced it.

## Rationale

Deterministic selection supports reproducible and auditable projections. Exact references retain their meaning across provider rendering and handoff.

## Consequences and compatibility

Record the projection identity, Work Item, target provider, exact source revisions or digests, canonical payload, digest, timestamp and applied policy and redaction. Adapter Manager renders provider-specific output downstream. The same inputs must reproduce the projection. A source change must change its digest. Derived context has no authority to alter its sources.

## Alternatives

v0.1 needs no vector database. Later embeddings may supplement exact retrieval while exact references remain the basis of provenance.

## Affected phases

Phase 4 implements deterministic indexing, immutable projections and audit. Phases 5, 7 and 8 use them for switching, import and desktop inspection.

## Non-goals

Phase 0 records source and digest constraints. It adds no Context Engine, index, projection schema or embedding pipeline.

# DT-15 — Read-only discovery before external project import

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-15, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

External Git repositories need a route into Corinthos that preserves their source and distinguishes discoveries from owner-confirmed facts.

## Decision

Start Import Project with read-only discovery. Inspect the Git root, tracked files, manifests and configuration, documentation, tests, languages and extensions, Git state and any existing Corinthos artifacts. Use the observations to prepare a Project Registry entry, derived Initial Project State and Context Index. Present discoveries and confirmations separately before permitting mutable Work Items.

## Rationale

Read-only discovery protects the existing repository and gives the user a chance to resolve ambiguity before changes begin.

## Consequences and compatibility

Check the root and permissions, and verify that discovery leaves the repository unchanged. Preserve existing project data and approval boundaries. Architecture remains subject to confirmation and approval through the appropriate workflow.

## Alternatives

Specialized indexing adapters may extend the importer. Graphify is an optional integration if its license, API and stability permit it. Core has no mandatory Graphify dependency.

## Affected phases

Phase 7 implements and verifies read-only import. Phase 8 exposes it in the desktop workflow.

## Non-goals

Phase 0 adds no importer, scanner or index. Import alone confers no architecture approval.

# DT-11 — Provider-independent Agent Sessions

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-11, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

The baseline introduced a generic Provider Registry in Phase 6.5. Phase 6.5.1 separated setup from active probing. The v0.1 supervisor needs to use these boundaries while retaining continuity across provider changes.

## Decision

Evolve the existing provider interface and registry. An Agent Session records its provider, observed version and model, Work Item, Context Projection, state, events, outputs, best-effort usage and cost, handoff and timestamps. A provider switch creates a new Agent Session. Native resume is permitted only for the same provider and the same authorized context.

## Rationale

The Work Item and Corinthos-owned context carry continuity. Native sessions retain their provider-specific lifecycle.

## Consequences and compatibility

Preserve precedence from operation override through project choice, per-user choice and safe discovery. Setup and startup leave optional providers unexecuted. Capabilities and refresh require an explicit request or an operation that genuinely needs the provider. The GUI can read known observations and offer explicit refresh. Cached observations carry no execution authority.

## Alternatives

Cross-provider native resume is excluded. The substitution gate needs at least two independent, genuinely supported providers. Codex and Claude are one possible pair when both are available.

## Affected phases

Phase 1 preserves read-only startup. Phase 3 evolves the adapters and adds the supervisor. Phases 4, 5 and 8 provide projections, switching and desktop presentation.

## Non-goals

Phase 0 records the boundary. Agent Session persistence, supervision and switching are scheduled for later phases.

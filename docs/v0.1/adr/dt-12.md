# DT-12 — Conservative execution concurrency

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-12, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

Command needs to show and operate multiple projects. The baseline Workflow runtime already relies on fencing and inspected recovery for mutable execution.

## Decision

Allow different projects to execute concurrently. Limit each project to one mutable Agent Session in v0.1. Diagnostics and read-only activity may coexist where safe.

## Rationale

Multi-project operation can use the existing isolation model while preserving fencing and recoverability within each project.

## Consequences and compatibility

Apply the writer limit at the project boundary. A provider switch must record the prior session as suspended or terminal and bind its successor to the correct projection before completion. Preserve existing authority and recovery guarantees as the supervisor evolves.

## Alternatives

Defer same-project mutable parallelism to a later design with leases by Work Item or module.

## Affected phases

Phase 3 establishes the supervisor and writer rule. Phase 5 exercises interrupted switching. Phase 8 presents multi-project operation in Command.

## Non-goals

Phase 0 adds no scheduler or lease mechanism. Concurrent mutable sessions within a project are outside v0.1.

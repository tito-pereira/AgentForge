# DT-18 — Provider telemetry is best-effort

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-18, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

Providers expose different usage and model information. Some invocations omit metrics or lack a reliable cost report.

## Decision

Normalize input and output tokens, cached tokens, duration, reported cost, provider, model and version when observable. Represent unavailable telemetry as `UNKNOWN`.

## Rationale

Known measurements and unknown observations must remain distinguishable so that comparisons and reports describe what was actually observed.

## Consequences and compatibility

Persist normalized usage and cost evidence as part of the Agent Session work. Display `UNKNOWN` when no observation exists. Record zero only when supported by the observation. Preserve existing provider and Validation authority.

## Alternatives

Invented zeros are excluded. The Phase 9 roadmap treats any future product telemetry collection as opt-in.

## Affected phases

Phase 3 normalizes session events and persists usage. Phase 8 presents telemetry in Command. Phase 9 covers any future opt-in telemetry collection.

## Non-goals

Phase 0 adds no collection, estimates, persistence or reporting. This decision does not require analytics or equivalent telemetry coverage across providers.

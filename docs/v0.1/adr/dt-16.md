# DT-16 — Secrets stay outside databases

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-16, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

The desktop and headless paths need provider authentication. Project SQLite and the Core Registry serve other purposes and can be inspected or exported.

## Decision

Keep API keys and tokens out of `state.db` and the Core Registry. Use the operating system credential store for desktop. Use environment variables for CLI, headless execution and CI. Keep secret values in memory during execution and redact them from logs and reports.

## Rationale

Keeping credentials at the authentication boundary prevents persistent project and convenience records from becoming a secret store.

## Consequences and compatibility

Keep existing provider selection and project authority separate from credential handling. Ensure diagnostics and exported evidence redact secret values. Phase 4 also applies the roadmap's redaction policy to Context Projections.

## Affected phases

Phase 4 applies context redaction. Phase 9 delivers desktop credential-store integration and log redaction.

## Non-goals

Phase 0 adds no credential storage, authentication flow or redaction implementation.

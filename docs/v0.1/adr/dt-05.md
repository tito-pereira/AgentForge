# DT-05 — Keep the Rust Core at the desktop boundary

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-05, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

Tauri requires Rust for native desktop integration. Python already owns
the rules and authority of the Workflow Standard.

## Decision

Limit Rust to sidecar lifecycle, IPC, capability permissions, necessary
desktop integration and packaging or updater integration where
applicable. Keep rules, contracts, authorization, context and workflow
in Python.

## Rationale

The desktop bridge can manage native permissions and process lifecycle
without creating a second implementation of product decisions.

## Consequences and compatibility

The bridge routes work to the [Application API](dt-06.md) and cannot grant
contract publication authority. Product and project state continue to be
owned by their existing services and stores.

## Affected phases

Phase 1 proves the boundary. Phases 8 and 9 apply it to the functional
desktop, permissions and packaging.

## Scope exclusions

Rust or frontend implementations of product rules, a separate approval
path and an updater commitment during Phase 0 are outside scope.

# DT-17 — Version the desktop bridge protocol independently

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-17, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

GUI and CLI will share an Application Layer. The desktop bridge needs a stable schema boundary while the eight canonical contract wire formats retain their own compatibility rules.

## Decision

Define explicit bridge schemas for request, response, error, event, Project Summary, Work Item, Agent Session, Context Projection summary and approval request. Give the protocol its own version.

## Rationale

Independent protocol versioning allows bridge compatibility to be managed without implicitly changing a contract wire format or a persistence version.

## Consequences and compatibility

Phase 1 defines RPC v1 and the bridge lifecycle, including handshake, events and graceful shutdown. Subsequent phases fill out the DTOs as their services arrive. An approval request remains subject to the existing authority model. Coordinate public desktop, package, RPC, contract wire and SQLite versions before release while preserving their independence.

## Affected phases

Phase 1 defines the protocol. Phases 2–4 add the project, session and context surfaces. Phase 8 uses the bridge in Command.

## Non-goals

Phase 0 creates no active RPC schemas or implementation. Public release versioning remains a separate owner decision.

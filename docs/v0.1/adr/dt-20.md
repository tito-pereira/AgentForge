# DT-20 — Preserve the platform boundary

**Status** — Approved roadmap decision.

**Source** — Corinthos v0.1 Architecture and Roadmap, DT-20, version consulted 2026-11-13.

**Baseline provenance** — [Initial v0.1 baseline commit](https://github.com/tito-pereira/Corinthos/commit/5a2a8e682b1389d96318feb636b8f52828f943d3).

## Context

Phase 6.5 separated Windows distribution from the existing Python Core through `platform/windows`. The backend is verified on Windows and Ubuntu.

## Decision

Keep domain and contract logic platform-neutral. Put global paths, install and runtime integration, and genuinely OS-specific discovery behind platform seams. Windows is first-class for desktop and installation in v0.1. Linux and Ubuntu remain backend and CI targets.

## Rationale

Explicit platform boundaries preserve backend portability and allow platform integrations to evolve without bringing Windows assumptions into Workflow Standard.

## Consequences and compatibility

Keep `LOCALAPPDATA`, PowerShell, registry and Tauri or Windows assumptions outside Workflow Standard. Preserve the existing Windows distribution seam, per-project format and backend CI targets. Preserve the current Python package and import root across the conceptual naming change.

## Alternatives

Linux desktop and packaging are deferred and do not gate v0.1.

## Affected phases

Phase 0 records the seam. Phase 1 establishes the desktop boundary. Phase 8 integrates the GUI. Phase 9 hardens Windows installation and preserves cross-platform backend coverage.

## Non-goals

Phase 0 creates no new platform layer. A Linux desktop installer and broad module moves are outside its scope.

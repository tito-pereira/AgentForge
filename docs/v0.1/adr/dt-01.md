# DT-01 — Keep Python as the domain core

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-01, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The existing `corinthos` package owns the Corinthos Workflow Standard,
including contract authority, persistence, provider integration and
validation. The public `corinthos-core` package at version `0.1.0`
declares Python `>=3.12`. The Windows source installer pins its
private CPython 3.14.10 embeddable x64 runtime.

## Decision

Keep the Workflow Standard, persistence, context, provider integration,
validation and application logic in Python. Preserve the distinction
between source/package compatibility and the private runtime managed by
the Windows installer.

## Rationale

Python already has tested domain behavior. Rewriting the domain in Rust
or TypeScript would discard that work without addressing the desktop
integration problem.

## Consequences and compatibility

Keep the `corinthos` import root and package compatibility metadata.
The Phase 0 baseline verifies CPython 3.12 and 3.14.10 on Windows and
Ubuntu. Python 3.15 remains unverified. Desktop components may use
Rust and TypeScript within their [desktop boundary](dt-05.md).

## Affected phases

Phase 0 records the baseline. Phases 1–9 inherit the Python domain
boundary, including the sidecar and installer work in Phases 1 and 9.

## Scope exclusions

Rust or TypeScript rewrites of the domain, a package rename and a private
runtime version change are outside this decision.

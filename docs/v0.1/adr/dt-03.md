# DT-03 — Supervise one long-lived Python sidecar

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-03, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The Windows installer already provisions a private CPython 3.14.10
embeddable x64 runtime and the Corinthos application. The desktop needs
a local backend it can start, communicate with and stop.

## Decision

Have Tauri start and supervise one long-lived Python process that
contains the Application Service Layer and Workflow Standard. First
attempt to reuse the existing installed private runtime and application.

## Rationale

Reusing the installation avoids maintaining two independent packaging
mechanisms for the same backend. The sidecar belongs to the desktop
lifecycle and IPC boundary and uses the existing domain rules and state.

## Alternatives

PyInstaller remains conditional on a spike demonstrating a material
distribution, isolation, startup or Tauri integration benefit that the
installed private runtime cannot provide.

## Consequences and compatibility

Exercise repeated startup and graceful shutdown without orphan
processes in Phase 1. Initial GUI queries can show known or cached
provider capabilities. Follow the explicit provider execution boundary
in [DT-11](dt-11.md).

## Affected phases

Phase 1 proves lifecycle and IPC with the private runtime. Phase 9
verifies distribution and integration in the source installer.

## Scope exclusions

A second backend package or project store, an automatic PyInstaller
migration and a sidecar implementation during Phase 0 are outside scope.

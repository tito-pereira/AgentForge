# DT-07 — Preserve project-local state and evolve the existing per-user state

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-07, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

Projects already keep operational state in `.corinthos/state.db`. The
Windows installation already uses `%LOCALAPPDATA%\Corinthos` for
`config.json`, `recent-projects.json`, `logs/` and `cache/`. Explicit
provider operations use the optional `providers.json` in the same store.

## Decision

Retain the database as the project's operational source. Evolve the
existing versioned per-user store for product and GUI metadata, known
projects, last access and non-sensitive preferences.

## Rationale

The product needs multi-project navigation and preferences. It can
reuse the existing global state while retaining each project's authority
and isolation.

## Consequences and compatibility

Preserve compatibility with the Phase 6.5 installation and use versioned
global state migrations. Contracts, Workflow, Validation, Report and
lifecycle retain their project-local sources of truth. The per-user store
does not duplicate Project State.

## Affected phases

Phase 0 records both storage scales. Phase 2 evolves the existing global
state and Recent Projects for the Project Registry. Phases 8–9 consume
and verify compatibility with the desktop and installation.

## Scope exclusions

A second global registry, central copies of authoritative project state,
and changes to global state storage in Phase 0 are outside scope.

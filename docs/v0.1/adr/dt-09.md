# DT-09 — Compose Project State as a read model

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-09, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The planned application needs a coherent view of a project whose facts
already belong to multiple canonical and operational sources.

## Decision

Create a `ProjectStateService` that composes contracts, requirements,
decisions, modules, lifecycle, Work Items, Agent Sessions, Validation,
evidence, events and derived context. The UI can keep disposable
snapshots as caches.

## Rationale

A derived read model can change presentation without creating competing
canonical state. Each source keeps its existing owner.

## Consequences and compatibility

Rebuild the view from the relevant project sources as they become
available. Preserve exact references and existing write paths. UI
snapshots and [per-user state](dt-07.md) have no authority over
contracts or operational records.

## Affected phases

Phase 2 introduces the service and Project Summary API. Phases 3–4 add
session and context sources. Phases 7–8 use the read model for imported
projects and the desktop views.

## Scope exclusions

A monolithic `project_state.json`, a monolithic canonical table and a
Project State implementation during Phase 0 are outside scope.

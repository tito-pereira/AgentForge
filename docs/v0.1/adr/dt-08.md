# DT-08 — Keep sqlite3 and incremental migrations

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-08, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The project's SQLite v6 state already uses the standard-library
`sqlite3` module with explicit repositories and migrations.

## Decision

Continue with `sqlite3` and the current repository and migration
pattern. Add new entities through incremental schema versions and
verified backups.

## Rationale

The existing storage model provides the transaction and recovery
boundaries needed for incremental evolution. The roadmap identifies
no need for SQLAlchemy solely to replace a working persistence layer.

## Consequences and compatibility

Use a valid previous-version database fixture for each migration.
Verify the application marker, integrity and foreign keys, preserve the
original in a backup, and test transactional rollback and reopen.
Preserve existing contracts, revisions and `wf_*`, `val_*` and `lc_*`
state in their current stores.

## Affected phases

Phase 0 freezes the SQLite v6 compatibility contract. Phase 2 introduces
v7 for Work Items and related project metadata. The roadmap assigns v8
to Phase 3 sessions and v9 to Phase 4 context projections and handoffs.

## Scope exclusions

A mandatory ORM, a one-step migration to a final schema, duplicated
tables for existing data and v7 migration code in Phase 0 are outside
scope.

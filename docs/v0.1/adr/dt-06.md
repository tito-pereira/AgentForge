# DT-06 — Share one Application API between the GUI and CLI

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-06, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

At the baseline the CLI dispatches to existing domain services. Calling
`corinthos` with no arguments opens the terminal Home, and `corinthos .`
opens the project at the current directory.

## Decision

Introduce `corinthos.application` as the stable application boundary.
The GUI calls it through the sidecar bridge and the CLI progressively
replaces direct calls to concrete engines and repositories with calls to
the same layer.

## Rationale

Equivalent operations from either interface must produce the same
canonical effect. Sharing the API lets both surfaces reuse the same
domain behavior and authority.

## Consequences and compatibility

When the functional desktop is installed, `corinthos` with no arguments
opens the main GUI. `corinthos <subcommand> ...` remains a scriptable,
headless CLI over the shared API. The current terminal Home remains
available for fallback, debugging and tests.

## Affected phases

Phase 1 establishes the API and read-only integration. Subsequent
phases route new services through it. Phase 8 completes the functional
GUI and GUI/CLI equivalence gate.

## Scope exclusions

Phase 0 does not introduce an application implementation, switch the
default launcher, or create parallel implementations of the existing
services.

# DT-04 — Use message-delimited JSON-RPC 2.0 over stdio

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-04, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The React webview needs a bounded request and event channel to the local
Python backend.

## Decision

Send requests from React through Tauri invoke to the Rust Core.
The Rust bridge communicates with the Python sidecar using JSON-RPC 2.0
over message-delimited stdio, with request IDs and notifications or
events. The sidecar routes operations to Application Services.

## Rationale

Stdio avoids local listening ports, loopback authentication and service
discovery, reducing the attack surface.

## Consequences and compatibility

The webview has no permission to start arbitrary processes and does
not communicate directly with agent executables. The [versioned desktop
protocol](dt-17.md) remains distinct from the existing contract wire
format.

## Affected phases

Phase 1 defines and proves the protocol, handshake, events and graceful
shutdown. Phases 8–9 apply the bridge and desktop capability boundaries
to the complete product.

## Scope exclusions

Local HTTP transport, direct webview-to-agent execution and any active
RPC implementation during Phase 0 are outside scope.

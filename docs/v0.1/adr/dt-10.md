# DT-10 — Use Work Item as the universal unit of work

**Status** — Approved roadmap decision.

**Source** — *Arquitetura e Roadmap v0.1*, DT-10, consulted November 13, 2026.

**Baseline provenance** — [Phase 0 compatibility baseline](../baseline.md).

## Context

The existing engineering workflow serves substantial projects. The
v0.1 model also needs to represent smaller tasks and changes with
verification proportionate to their scope.

## Decision

Introduce a persistent Work Item carrying `work_item_id`, `project_id`,
`parent_work_item_id`, `scope_level`, objective, acceptance criteria,
state, affected modules, dependencies, validation policy and provenance.
The scope levels are `TASK`, `CHANGE`, `PROJECT` and `CRITICAL`.

## Rationale

One durable work unit supports both reduced and full workflow paths and
provides a stable context for agents and project views.

## Consequences and compatibility

`PROJECT` and `CRITICAL` reuse existing workflows and contracts.
`TASK` and `CHANGE` use reduced paths with applicable verification.
A scope recommendation carries no Validation or approval authority.
The owner can elevate scope, reduction despite risk signals requires
confirmation, and `CRITICAL` cannot be silently downgraded.

## Affected phases

Phase 2 adds Work Item persistence and services. Phases 3–5 consume Work
Items in sessions, context and provider switching. Phase 6 implements
adaptive workflow paths, which Phases 7–8 expose through import and the
desktop.

## Scope exclusions

Work Item runtime and persistence, adaptive execution and changes to the
eight existing canonical contract families are outside Phase 0.
